class EmailSender:
    def send(self, to: str, msg: str) -> None:
        print(f"  [EMAIL -> {to}] {msg}")


class OrderService:
    def __init__(self) -> None:
        self.completed: list[int] = []
        self.sender = EmailSender()  # [A]

    def complete_order(self, order_id: int, customer: str) -> None:
        self.completed.append(order_id)  # [B]
        self.sender.send(customer, f"주문 {order_id}번 음료가 준비되었습니다.")  # [C]

확인 구역 위 ①~④를 모두 쓴 뒤에 펼쳐 읽는다. 내 문장과 대조해 같은 점·다른 점을 적는다.

개념 확인 펼치기 (일반화 문장을 쓴 뒤 열어 보세요)

개념 확인: DIP (Dependency Inversion Principle, 의존 역전 원칙)

  • 정의: 고수준 모듈은 저수준 모듈에 의존해서는 안 된다. 둘 다 추상에 의존해야 한다. 추상이 세부 사항에 의존해서는 안 되며, 세부 사항이 추상에 의존해야 한다.
  • '역전'의 뜻: 실행할 때 호출 흐름(고수준 → 저수준)은 그대로다. 바뀌는 것은 소스 코드의 의존 방향이다. 저수준 구현이 고수준이 정한 약속을 향해 화살표를 그리게 된다.

개념 확인: 고수준 모듈 / 저수준 모듈

  • 고수준: "무엇을 할지"를 정하는 업무 규칙(주문이 완료되면 고객에게 알린다).
  • 저수준: "어떻게 할지"를 맡는 세부 수단(이메일, 카카오톡, 파일, DB).
  • 코드와 연결: s3_notifier.py 주석의 "업무 규칙 쪽"이 고수준, "수단 쪽"이 저수준이다.
  • 추상은 누구 것인가: 추상(약속)은 고수준이 필요로 하는 모양으로 정한다. 그래서 2차시의 "필요한 만큼만 작은 약속"(ISP)이 DIP의 추상이 된다.

개념 확인: 의존성 주입 (Dependency Injection, DI)

  • 정의: 객체가 쓸 협력 객체를 스스로 만들지 않고 바깥(조립 지점)에서 넣어 받는 기법. 생성자 주입이 가장 흔하다.
  • DIP와의 관계: DI는 DIP를 이루는 수단 중 하나일 뿐이다. 구체 클래스 타입을 주입받으면 주입은 했지만 의존 방향은 그대로다.
내 문장과 같은 점내 문장에 없던 것 / 다르게 쓴 것

class CsvWriter:  # [B]
    def write(self, row: list) -> None: ...

class WeatherStation:
    HOT = 30.0

    def __init__(self) -> None:
        self.sensor = ThermoSensorV2()  # [C]
        self.writer = CsvWriter()  # [D]

    def record(self, hour: int) -> None:
        temp = self.sensor.read()  # [E]
        status = "경고" if temp >= self.HOT else "정상"
        self.writer.write([hour, temp, status])
