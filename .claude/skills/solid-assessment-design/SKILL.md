# SOLID 평가 문항 출제 규칙

## 산출물 (파일 3종 분리, 코드는 code/에 공유)
위치 `solid_course/assessment/`
| 파일 | 대상 | 내용 |
|------|------|------|
| `exam.html` | 학생 | 문제 5개, 배점, 시작 코드(복사용 pre). **정답·힌트 없음** |
| `hints.html` | 학생(풀다 막힐 때) | 문제별 단계 힌트(1단계 방향 → 2단계 핵심 개념 → 3단계 구조 뼈대). `<details>`로 단계별 열람. **정답 코드 금지** |
| `answers.html` | 교사 | 모범 정답, 채점 기준표(루브릭), 흔한 오답, 정답 코드. 교사 배너 |
| `code/qN_*.py` | 공유 | 시작 코드(문제용) / `code/solutions/qN_*.py` 정답 코드(assert 포함) |

스타일은 기존 `assets/style.css`(+교사용 `teacher.css`), 코드 하이라이팅은 `assets/highlight.js`를 연결한다(실행 결과 블록은 `<code class="out">`). 한국어, Python 3.12+.

## 문항 설계 (총 5문항, 100점)
세 가지 능력을 모두 측정한다. 각 문항의 제목에 **[능력] [원칙]**과 배점을 표기한다.
| 능력 | 측정 방식 |
|------|-----------|
| 개념 이해 | 정의 설명, 유사 원칙 구별, 상황에서 원칙 판단, 과잉 적용 판단 |
| 코드 분석 | 위반 지점 찾기, 위반 근거 서술, 실행 결과 예측, 변경 시 영향 범위 추적 |
| 구현 | 리팩터링, 새 기능 추가, 추상화 설계 — 정답 코드가 assert로 검증 가능해야 함 |

필수 분포: 5원칙(SRP·OCP·LSP·ISP·DIP) 각각 최소 1문항에서 직접 다루고, 개념·분석·구현이 각각 최소 1문항 주 능력이 되도록 한다. 한 문항이 두 능력을 겹쳐 측정해도 좋으나 소문항(1)(2)(3)로 나누고 소문항별 배점을 둔다. 권장 배치: Q1 개념, Q2~Q3 분석, Q4~Q5 구현(Q5는 종합: 분석+구현).
난이도: 쉬움 1 / 보통 2~3 / 어려움 1~2. 암기가 아닌 **새로운 상황 적용**이어야 하므로 수업 학습지·교재와 도메인을 겹치지 않는다(카페·택배·새·도서관 등 사용 금지).

## 문항 품질 규칙 (왜: 채점 타당성)
- 학습목표 대신 **측정 요소**를 명시: 문항마다 "측정 요소" 1~3개를 answers.html에 표로 연결한다.
- 모호성 제거: 구현 문제는 입력·출력·클래스/함수 이름을 지정하고, 허용 해법이 여러 개면 채점 기준에 모두 인정 범위를 적는다.
- 서술형 정답은 "필수 요소" 체크리스트로 채점 가능하게 분해한다(요소당 배점).
- 구현 문제에는 학생이 자기 코드를 돌려볼 수 있는 **공개 테스트 코드**(문제에 포함)와, 채점용 추가 케이스(answers에만)를 둔다. 공개 테스트를 통과해도 구체 타입 분기·하드코딩으로 우회한 답은 감점되도록 채점 기준에 "우회 오답"을 명시한다.
- 코드 분석 문항의 "실행 결과 예측"은 반드시 실제로 돌려 확인한 값만 정답으로 쓴다.

## 힌트 자료 규칙
- 힌트는 정답을 대신 말하지 않는다. 3단계: ① 무엇을 먼저 볼지(질문형) ② 관련 원칙의 판단 기준 ③ 풀이 구조 뼈대(빈칸 포함, 정답 로직 제외).
- 문제 해결 도움 자료로 5원칙 한 줄 판별 질문 요약표를 hints.html 앞부분에 둔다.

## 검증
- 모든 시작 코드는 그대로 실행되고(위반 상태 동작), 정답 코드는 assert 통과, 시작 코드는 공개 테스트 중 구조 요구를 의도적으로 못 맞춘다.
- exam.html에 정답 단어(모범 답 문장)가 없는지 grep, hints.html에 정답 코드가 없는지 점검한다.
